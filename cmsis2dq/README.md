# cmsis2dq

Native DQ port of `dq-lang/tools/cmsis2dq.py`, using the standard `regexp`
package. The parser converts CMSIS register structures, unions, explicit enum
values, numeric macros and peripheral pointers to DQ declarations.

```sh
make
./cmsis2dq device.h > device.dq
./cmsis2dq --no-comments device.h -o device.dq
make test
make install PREFIX="$HOME/.local"
```

`DQ_COMP` and `DQ_RUN` can select another compiler and test runner. Python is
not needed to build, run or test this project. `make test` compares against
fixtures generated by the original Python script and checks constant block
boundaries, line continuations and parser reuse.

The layout follows `dq-fromc`: `cmsis2dq.dqproj`, `Makefile`, and `src/`.
`main_cmsis2dq.dq` handles the command line and files; `cmsis_parser.dq` owns
parser state and declaration formatting; `c_expr.dq` handles expressions.
`OCmsisParser.Translate` can also be used directly from another DQ module.

The Python parser's behavior and output formatting are preserved. This is a
line-oriented converter, not a C preprocessor or full C parser: includes and
conditional compilation are not evaluated, function-like macros and unknown
constant references are skipped, and enums need explicit values. Unparsed
structure members are emitted as comments unless `--no-comments` is used.
Review the generated declarations before using them. The CLI also supports
`--help`, `-o`, and nonzero exit status for errors.

## DQ API observations

No missing language feature blocks this port. Two library conveniences would
simplify it:

- Literal string replacement: currently expressed with `StrSplit` / `StrJoin`
  in `OCExpression.ReplaceText`, including type-name and suffix normalization.
- Regexp replacement callbacks: operator mapping currently iterates
  `StartSearch` / `SearchNext` and copies the intervening slices.

Known constant names use the existing dynamic string array's `IndexOf`.
Its linear lookup is sufficient for the tested headers; a standard string set
could improve scaling for unusually large inputs.
